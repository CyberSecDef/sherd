# Conformance corpus format

The golden-file corpus that `QA-002` calls "the single highest-value test
asset". This document fixes the on-disk format so that `pkg/format` can be
written against it rather than the other way round.

The harness lives in `internal/conformance/`; the corpus lives in
`testdata/conformance/`. They are separate because the Go tool ignores any
directory named `testdata`, so no test can live inside one.

## Two sources of cases

### 1. The vendored CommonMark suite

`testdata/conformance/commonmark/spec.json` — 652 cases, read directly and
unmodified. Each upstream case supplies `markdown` and `html`, so CommonMark
cases exercise **HTML comparison only**. `FR-MD-001` requires 100% of these to
pass.

### 2. Sherd cases

`testdata/conformance/sherd/<category>/<case-name>/`, one directory per case:

```
input.md          required — the source document
output.html       optional — expected rendered HTML
ast.json          optional — expected AST, including byte ranges
metadata.json     optional — expected extracted metadata
```

A case runs whichever comparisons it provides. Omitting a file means "not
asserted here", never "no expectation".

## `ast.json`

```jsonc
{
  "type": "document",
  "range": [0, 27],
  "children": [
    { "type": "paragraph", "range": [0, 11], "children": [
        { "type": "text", "range": [0, 11], "literal": "Hello world" } ] },
    { "type": "wikilink", "range": [13, 27], "attrs": {
        "target": "Other Note", "display": "", "subpath": "" } }
  ]
}
```

| Field | Required | Meaning |
|---|---|---|
| `type` | **yes** | Node kind, lower-case |
| `range` | **yes** | `[startByte, endByte)` into `input.md`, half-open |
| `children` | no | Child nodes, in source order |
| `literal` | no | Literal text for leaf nodes |
| `attrs` | no | Node-specific attributes, keys sorted |

**`range` is mandatory on every node, and the harness rejects an AST without
it.** This is deliberate. `FR-MD-003` requires byte-offset ranges for
source↔render mapping and surgical edits; `PLAN.md` risk R3 is that ranges get
retrofitted later, at which point live preview, incremental parse (`FR-MD-004`),
and the surgical frontmatter writer (ADR 0004) all become rewrites. Making the
corpus refuse a range-less AST removes the option of deferring it.

Ranges must satisfy: `0 <= start <= end <= len(input)`, every child's range
contained by its parent's, and siblings non-overlapping and ordered.

## `metadata.json`

Mirrors the index schema in specification §8.2, so a case asserts exactly what
`internal/index` will store.

```jsonc
{
  "properties": [ { "key": "title", "type": "text", "value": "Hello" } ],
  "links":      [ { "target": "Other Note", "subpath": "#Heading",
                    "display": "alias", "kind": "wiki",
                    "range": [13, 27], "line": 3 } ],
  "tags":       [ { "tag": "project/alpha", "source": "inline",
                    "range": [40, 54], "line": 5 } ],
  "headings":   [ { "level": 2, "text": "Section", "slug": "section",
                    "path": "Top#Section", "range": [0, 9], "line": 1 } ],
  "blocks":     [ { "id": "abc123", "range": [60, 80] } ],
  "tasks":      [ { "status": " ", "text": "do the thing",
                    "line": 7, "indent": 0 } ],
  "embeds":     [ { "target": "Image.png", "subpath": "", "line": 9 } ]
}
```

Every array is optional; an absent array asserts nothing, an empty array
asserts emptiness. `kind` is one of `wiki`, `markdown`, `embed`, `frontmatter`,
`canvas`. `source` is `inline` or `frontmatter`.

## Adding cases

- **A parser change grows the corpus in the same commit** — not the next one.
- **A bug fix adds a case that fails before the fix** (`QA-012`).
- Cases are hand-written or generated by Sherd. Never copied from another
  project's suite; the vendored CommonMark suite is the sole exception, and it
  is licensed for it.
- No real personal notes, and no third-party branding (`LEG-003`).

## Expected failures

`testdata/conformance/expected-failures.txt` lists cases known not to pass yet,
one identifier per line. The harness treats the file as a **ratchet**:

- A listed case that fails → reported as pending, build stays green.
- A listed case that **passes** → build **fails**, telling you to delete the
  line. Progress cannot be silently lost.
- An unlisted case that fails → build fails, as a regression.

During P0 this file shrinks commit by commit, and the diff is the progress
report.
